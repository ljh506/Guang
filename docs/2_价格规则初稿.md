# 拾光Agent · 价格规则引擎初稿

> 版本：v0.1
> 设计原则（计划书 §四）：**AI负责识别，规则负责定价**。价格由预设、可解释的规则引擎计算，不依赖大模型自由生成。
>
> **产品机制（本次更新）**：规则引擎输出的 `estimated_min / estimated_max` 为**建议估价区间（参考价）**，仅供展示与用户参考；**真实成交标价（asking_price）由用户在发布页手动输入**，规则引擎不强制约束，仅在校验时给出提示（不阻断发布）。

## 1. 估价规则总览

估价公式：

```
estimated_min = round( original_price × 折扣区间下限 )
estimated_max = round( original_price × 折扣区间上限 )
```

输出固定为 `[estimated_min, estimated_max]` 闭区间，同时生成一段可读的"估价依据"文本（reason_text）。

**重要：该区间仅为AI+规则给出的建议估价区间（参考价）**，用于展示和辅助决策；**真实成交标价（asking_price）由用户在发布页手动输入**，规则引擎不做强制约束，仅在校验时提示（见 §4.5 / §6）。

## 2. 品相分级定义

| 品相等级 | condition 取值 | 判定标准（用户选择时参考） |
|---|---|---|
| 全新/较新 | `new_like` | 未拆封、或拆封后几乎无使用痕迹；无划痕、无磨损、无污渍；原包装/配件齐全 |
| 良好 | `good` | 有正常使用痕迹但无明显破损；轻微划痕/褪色；功能完全正常；包装可有可无 |
| 一般 | `fair` | 有明显使用痕迹；存在可接受的破损/磨损/功能部分受限；不影响基本使用 |

- 品相为**必填项**，由发布用户在表单中选择，不依赖AI判断（AI只识别类别）。
- 数据库 `Goods.condition` 存储上述三个取值之一；前端显示中文（全新/较新、良好、一般）。

**电子产品使用年限微调规则**（Day 6 细化，Day 1 先定框架）：
- 全新/较新档：使用年限 ≤ 6 个月取下限 0.7，7~18 个月取 0.75，> 18 个月取 0.8~0.85（可按实际折旧上调区间）。
- 良好/一般档：以年限作为区间内偏移依据，具体公式 Day 6 实现时与 A 接口联调确认。

## 4. 估价区间计算方式（建议参考价）

1. 入参：`original_price`（原价，必填）、`condition`（品相，必填）、`category_id`（类别，必填，来自AI识别或手动选择）。
2. 查折扣表得到 `[low, high]`。
3. `estimated_min = round(original_price * low)`；`estimated_max = round(original_price * high)`。
4. 特例：
   - 电子产品 + 全新/较新：按 §3 使用年限微调规则调整 high/low。
   - `original_price = 0`（免费赠送）：估价区间输出 `[0, 0]`，reason_text 注明"免费赠送"。
   - 四舍五入：按 Python `round()` 处理；结果为 0 但原价 > 0 时，min 至少取 1（避免出现 0 元但非赠送的异常展示）。

验证样例（计划书 §四 示例）：
- 输入：category=textbook，condition=good，original_price=68 → 查表 0.4~0.6 → **68×0.4=27.2→27，68×0.6=40.8→41** → 输出 **建议区间 27~41 元** ✓

### 4.5 用户手动标价（asking_price）机制

- `asking_price`（真实成交标价）由用户在发布页**手动输入**，为发布必需字段。
- 规则引擎不强制约束 asking_price，用户可填任何 ≥ 0 的数值（免费赠送填 0）。
- **标价校验规则（仅提示、不阻断）**：

| 用户标价 vs 建议区间 | 提示文案 |
|---|---|
| `asking_price < estimated_min` | "您的标价低于建议区间（{min}~{max} 元），可适当参考建议价" |
| `estimated_min <= asking_price <= estimated_max` | 不提示（或浅提示"标价在建议区间内"） |
| `asking_price > estimated_max` | "您的标价高于建议区间（{min}~{max} 元），可能影响交换成功率" |

- 校验方式：发布页提交前前端本地校验展示提示；后端估价接口可选返回 `price_tip` 字段（传入 asking_price 时），**任何情况下不阻断发布**。
- 示例流程：AI识别为教材 → 规则引擎给出 **27~41 元**建议区间 → 用户手动填写真实标价 **30 元** → 提交发布（30 元在建议区间内，提示可选显示）。

## 5. 估价依据文本模板（可解释性）

模板（reason_text，前端详情页/估价页展示"估价依据"——注意该文本描述的是**建议估价区间**，与用户手动填写的真实标价 asking_price 需区分展示）：

```
「{类别名}」{品相中文}，参考原价 {原价} 元，按{类别名}类{品相中文}折扣 {low}~{high} 计算，建议估价 {estimated_min}~{estimated_max} 元。
```

示例（68元良好教材）：
```
「教材」良好，参考原价 68 元，按教材类良好折扣 0.4~0.6 计算，建议估价 27~41 元。
```

- 免费赠送模板：`该物品选择免费赠送，估价为 0 元。`
- 电子产品额外附加：`已按使用年限 {n} 个月微调折扣区间。`
- 要求：reason_text 必须随估价接口返回，前端原样展示，**不得由前端自行拼接**。

## 6. 边界情况处理

| 场景 | 处理策略 |
|---|---|
| 原价缺失（null / 空） | 估价接口返回 400 + 错误码 `PRICE_ORIGINAL_REQUIRED`，提示"请填写参考原价"；免费赠送模式除外（见下） |
| 原价 ≤ 0 | 若交易方式为免费赠送：输出 [0,0]；否则按无效原价处理，返回 400，提示需 ≥ 0 |
| 原价异常大（> 100000） | 视为异常输入，返回 400 + 错误码 `PRICE_OUT_OF_RANGE`，提示"原价超出合理范围" |
| 原价非数字 / 含非法字符 | 前端校验 + 后端二次校验，返回 400 `PRICE_INVALID_FORMAT` |
| 品相缺省 / 非法取值 | 返回 400 `CONDITION_REQUIRED` / `CONDITION_INVALID`，**禁止默认猜测品相**（保证可解释性） |
| 类别非法 / 未在折扣表 | 返回 400 `CATEGORY_INVALID`；`other` 类别有折扣档，不阻断 |
| 计算结果 min > max | 理论上不发生（折扣表保证 low ≤ high）；若发生，返回 500 并记录日志，前端显示兜底文案"估价暂时不可用，请稍后重试" |
| 免费赠送 | condition 仍必填（用于展示），但估价恒为 [0,0]，reason_text 走赠送模板；用户标价应填 0 |
| 用户手填标价 asking_price | 任何 ≥ 0 的数值均接受，**不阻断发布**；超出建议区间时返回 price_tip 提示文案（见 §4.5） |

## 7. 接口约定草案（供成员A联调，Day 6 正式实现）

**估价接口（POST /estimate）**

```
请求：
{
  "category_id": "textbook",        // 必填
  "condition": "good",              // 必填：new_like / good / fair
  "original_price": 68,             // 必填：数字，元（用于计算建议区间）
  "is_free": false,                 // 可选：免费赠送标记
  "device_age_months": null,        // 可选：电子产品使用年限（月），仅 electronics 生效
  "asking_price": null              // 可选：用户已手填的真实标价；传入时返回 price_tip 校验提示
}

响应：
{
  "success": true,
  "data": {
    "estimated_min": 27,            // 建议估价区间下限（参考价，仅供展示）
    "estimated_max": 41,            // 建议估价区间上限（参考价，仅供展示）
    "reason_text": "「教材」良好，参考原价 68 元，按教材类良好折扣 0.4~0.6 计算，建议估价 27~41 元。",
    "rule_ref": {"category": "textbook", "condition": "good", "low": 0.4, "high": 0.6},
    "price_tip": null               // 可选：标价校验提示文案；null 表示无需提示（未传 asking_price 时恒为 null）
  }
}
```

**字段说明（重要）**：
- `estimated_min / estimated_max / reason_text` 为**建议估价区间与依据**，仅作展示参考。
- **真实成交标价 asking_price 不由本接口生成**：用户在发布页手动输入后，随发布请求（POST /goods）提交 `asking_price` 字段；服务端可调用标价校验逻辑（见 §4.5）返回 `price_tip`，**仅提示、不阻断发布**。

错误响应统一：`{"success": false, "error_code": "...", "message": "..."}`，错误码见 §6。

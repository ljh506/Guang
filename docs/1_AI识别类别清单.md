# 拾光Agent · AI识别类别清单（成员B Day 1 交付）

> 版本：v0.1（Day 1 初稿，需求冻结版）
> 状态：待 Day 2 起在代码中落地为类别标准化常量，供前端展示、AI识别结果映射、价格规则引擎共用。

## 1. 设计原则

- 分类体系以计划书「四、AI识别与规则估价」的教材 / 电子产品 / 生活用品 / 衣物四大类为基础，扩展为 **9 个一级类别 + 1 个兜底类别**，覆盖校园闲置主流场景。
- 每个物品只归属 **一个一级类别**（必要时可附加二级标签，Day 4 再细化，Day 1 不做强制）。
- 类别 ID 使用稳定的英文小写 snake_case，作为后端存储、前端展示、AI识别映射的统一标识。
- AI 识别失败或置信度过低时，**必须走兜底策略**（见 §5），任何情况下不阻断发布流程。

## 3. 类别与识别置信度

- AI 识别输出：`category_id` + `confidence`（0~1，前端展示为百分比）。
- 置信度阈值约定：
  - `confidence >= 0.80`：自动填充类别，前端高亮展示置信度；
  - `0.60 <= confidence < 0.80`：自动填充类别，但提示"识别置信度较低，请人工确认"；
  - `confidence < 0.60`：不自动填充，直接进入手动选择流程（兜底）。

## 4. 识别结果映射规则

- 识别服务返回的原始标签需映射到上表类别ID（不同免费视觉服务的标签体系不同，映射表由成员B维护，Day 2 封装 AI 接口时落地）。
- 示例映射：`"book"/"textbook"/"math book"` → `textbook`；`"laptop"/"notebook computer"` → `electronics`；`"t-shirt"/"jacket"` → `clothing`。
- 无法映射的原始标签 → 归入 `other`。

## 5. 兜底策略（AI识别失败时手动选择类别）

| 场景 | 策略 |
|---|---|
| AI服务不可用 / 超时 / 返回错误 | 发布页直接显示类别选择器（下拉/宫格），用户手动选择，**不阻断发布** |
| 置信度 < 0.60 | 不自动填充，弹出类别选择器，默认推荐最高置信度候选（若有） |
| 识别结果无法映射到已知类别 | 归入 `other`，用户可手动改为更精确类别 |
| 用户对自动结果不满意 | 类别字段始终可手动修改，以用户最终选择为准；若被修改，`ai_category` 保留原始识别结果用于复盘 |

- 发布流程（识别→估价→用户确认真实价格）：上传照片 → AI识别类别并展示置信度 → 规则引擎给出**建议估价区间（仅参考）** → **用户手动确认真实标价（asking_price）** → 提交发布。估价区间仅供用户参考，不强制约束真实标价。
- 前端交互约定：类别选择器选项 = 上表 10 个类别；手动选择后仍需展示"估价依据"（见价格规则初稿）；发布页在建议估价区间下方提供真实标价输入框，用户手动填写真实价格。
- 责任边界：**AI失败不得导致发布流程中断**（计划书 §十七 成员B责任边界）。

# 拾光Agent · 交换匹配规则初稿（成员B Day 1 交付）

> 版本：v0.1（Day 1 初稿）
> 设计原则（计划书 §五）：第一版**不训练机器学习模型**，采用可解释的规则匹配；匹配度 = 类别/意愿 50% + 价格接近 30% + 同校 20%。

## 1. 匹配维度总览

| 维度 | 权重 | 说明 |
|---|---|---|
| 类别匹配 + 用户意愿匹配 | 50% | 对方想要的类别 vs 我方物品类别；我方想要的类别 vs 对方物品类别（意愿表达） |
| 价格接近（基于真实标价） | 30% | 双方物品**用户手动填写的真实标价 asking_price** 的接近程度（不再使用建议估价区间） |
| 同校优先 | 20% | 双方同属一个学校（school_id 相同）得满分 |

基础条件（不满足则不进入匹配候选，直接不推荐）：
- 双方物品状态均为可交换（`Goods.status` 允许交换）；
- 双方已表达意愿：A 想要 B 的物品类别，且 B 想要 A 的物品类别（单向意愿仅计为低分候选，见 §3）。

## 2. 匹配度计算公式

```
MatchScore = 0.50 × Score_category_wish + 0.30 × Score_price + 0.20 × Score_school
```

- 总分范围：0 ~ 1（前端展示为百分比，如 85%）。
- 各分项均为 0 ~ 1 的浮点数。

## 3. 各维度打分规则

### 3.1 类别/意愿匹配（权重 50%，Score_category_wish）

意愿由用户在交换流程中表达（"我想换什么类别"），存储为 `wish_category_id`。

| 情形 | Score |
|---|---|
| 双向完全匹配：A 的物品类别 ∈ B 的意愿类别 **且** B 的物品类别 ∈ A 的意愿类别 | 1.0 |
| 双向类别匹配（无显式意愿，按双方在售物品类别互相对上） | 0.9 |
| 单向匹配：仅 A 的物品 ∈ B 的意愿（B 的物品不在 A 意愿中） | 0.5 |
| 类别完全不匹配 | 0.0（不进入候选） |

> 计划书示例（高匹配）：A 拥有《高等数学》想要《大学物理》，B 拥有《大学物理》想要《高等数学》→ 双向完全匹配 → Score_category_wish = 1.0。

### 3.2 价格接近（权重 30%，Score_price）——基于用户真实标价

以双方物品的**真实成交标价 asking_price**（用户手动填写）计算接近度，**不使用建议估价区间**（建议区间仅作参考，不代表用户真实期望价）：

- 差值比：`ratio = |asking_price_a - asking_price_b| / max(asking_price_a, asking_price_b)`
- 打分：`Score_price = 1.0 - ratio`（标价相同 → 1.0 完全接近；差一倍 → 0.0）
- 兜底：双方均免费赠送（标价均为 0 元）→ Score_price = 1.0；仅一方免费赠送 → 0.3（规则化中性偏低分），reason_text 注明"一方为免费赠送，价格维度按中性处理"。
- 说明：建议估价区间 estimated_min/estimated_max 仍展示在商品详情/交换页供用户参考，但**不参与匹配得分**。

### 3.3 同校优先（权重 20%，Score_school）

| 情形 | Score |
|---|---|
| 双方 school_id 相同 | 1.0 |
| 不同学校 | 0.0 |

> 比赛版仅支持本校交易（漂流墙以本校为边界），跨校场景 Day 1 不展开；若后续放开，跨校可给 0.3 分并标注"需线下自提/邮寄（暂缓）"。

## 4. 匹配阈值与排序策略

- **候选生成**：先过滤基础条件（§1），再计算所有候选的 MatchScore。
- **推荐阈值**：
  - `MatchScore >= 0.75`：标记为"高匹配"，置顶推荐，前端展示绿色"高匹配"标签；
  - `0.50 <= MatchScore < 0.75`：普通候选，按分数降序展示；
  - `MatchScore < 0.50`：不进入推荐列表（可在"我的交换"中看到但标记"匹配度较低"）。
- **排序**：总分降序；总分相同（±0.001）时按价格接近度（基于 asking_price）降序，再按发布时间近者优先。
- **上限**：推荐列表单次最多返回 20 条，避免前端渲染压力。
- **去重**：同一对 (user, goods) 已存在未完成的 Exchange 记录（status 为待确认/已确认）时，不重复生成推荐。

## 5. 可解释说明模板

匹配接口对每条推荐返回 `match_reason` 文本，供前端"匹配结果"页展示：

```
双方意愿匹配（{A物品类别}↔{B物品类别}），双方标价 {a_price} 元与 {b_price} 元接近度 {price_pct}%，{同校/跨校}，综合匹配度 {score_pct}%。
```

示例（计划书 §五 高匹配示例，A 标价 30 元、B 标价 32 元）：
```
双方意愿匹配（教材↔教材），双方标价 30 元与 32 元接近度 94%，同校，综合匹配度 97%。
```

## 6. 接口约定草案（供成员A联调，Day 9 正式实现）

**匹配接口（POST /exchange/match）**

```
请求：
{
  "user_id": 1,                // 发起匹配的用户
  "goods_id": 12               // 用户选择参与交换的物品（其真实标价 asking_price 由 Goods 表提供）
}

响应：
{
  "success": true,
  "data": [
    {
      "target_goods_id": 20,
      "target_user_id": 2,
      "match_score": 0.97,
      "score_detail": {
        "category_wish": 1.0,
        "price": 0.94,          // 基于双方真实标价 asking_price 计算
        "school": 1.0
      },
      "match_reason": "双方意愿匹配（教材↔教材），双方标价 30 元与 32 元接近度 94%，同校，综合匹配度 97%。"
    }
  ]
}
```

- 说明：匹配算法读取 `Goods.asking_price`（用户手填真实标价）计算价格维度得分；建议估价区间 `estimated_min / estimated_max` 仅作展示，**不参与匹配计算**。

- 意愿表达接口（POST /exchange/wish）：`{user_id, wish_category_id}`，用于存储用户"想换什么类别"。
- 错误响应统一 `{"success": false, "error_code": "...", "message": "..."}`。
